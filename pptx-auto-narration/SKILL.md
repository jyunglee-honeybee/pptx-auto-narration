# PPT 자동 발표 만들기 (노트 대본 → 음성 + 자동 클릭)

결과물은 원본을 복사해 만든 PPTX입니다.
- 슬라이드쇼를 시작하면 낭독, 애니메이션, 슬라이드 넘김이 클릭 없이 끝까지 진행됩니다.
- PowerPoint(Windows)의 '비디오 만들기'로 그대로 MP4로 내보낼 수 있습니다.
- 함께 주는 파일: 낭독 검토용 MP3, 슬라이드별 타임라인 표(`*_timeline.md`).

도구는 `scripts/narrate_pptx.py` 하나입니다. 하위 명령은 `inspect`, `parse`, `samples`, `tts`, `build`입니다. 필요한 것은 python3, lxml, numpy, Pillow, ffmpeg로, 없으면 설치합니다. 작업은 언제나 업로드 파일의 복사본으로 하고 원본은 건드리지 않습니다.

## 1. 덱 점검

```bash
python3 scripts/narrate_pptx.py inspect deck.pptx        # 슬라이드별 클릭 수, 노트 클릭 수, 불일치 표시
python3 scripts/narrate_pptx.py inspect deck.pptx -v     # 효과마다 시작 시각(ms), 대상 도형 이름·글자
```

**노트 형식.** 도구가 읽는 규칙입니다. `references/notes_format.md`에 예시가 있습니다.
- 첫 `▶ 클릭 1` 앞의 문장은 슬라이드가 열릴 때 읽습니다.
- `▶ 클릭 N`(또는 `▶ Click N`) 다음 문장은 N번째 클릭 효과와 함께 읽습니다. `(애니메이션 X초)`는 참고용 표기입니다.
- `【X초…】 문장`(또는 `【Xs…】`)은 클릭 뒤 X초에 나오는 효과(예: 글자 이름표)에 맞춰 읽을 문장입니다.
- 읽지 않는 줄: `※`로 시작하는 줄, `━━` 머리줄, `━━ 사용법 ━━` 블록 전체, `(보충` 표시 줄.

**노트가 이 형식이 아니거나 비어 있으면:**
- `inspect -v`로 클릭마다 무엇이 나타나는지 확인하고, 기존 노트와 슬라이드 글자를 바탕으로 클릭별 대본 초안을 이 형식으로 씁니다.
- 초안은 반드시 사용자에게 보여 주고 승인받습니다. 학술 내용을 지어내지 말고, 슬라이드와 노트에 있는 내용만 말로 풀어 씁니다.
- 승인받은 대본은 복사본의 노트에 써 넣습니다(python-pptx: `slide.notes_slide.notes_text_frame.text = ...`).

**클릭 수는 반드시 일치해야 합니다.** 슬라이드마다 노트의 마지막 `▶ 클릭 N`이 그 슬라이드의 클릭 애니메이션 수와 같아야 합니다. `inspect` 마지막 줄의 불일치 수가 0이 될 때까지 대본을 맞춥니다. 슬라이드가 열리면 저절로 나오는 효과(자동시작 묶음)는 클릭 수에 넣지 않습니다.

## 2. Azure 음성 준비 (사용자가 할 일 포함)

사용자가 할 일입니다. 한 번에 정리해서 안내합니다.
1. Azure 계정을 만들고 **Speech** 리소스를 만듭니다. 가격 등급은 **Free F0**로 해야 합니다. Foundry나 AI services 통합 리소스는 S0로 잡혀 요금이 나올 수 있어 피합니다.
2. claude.ai 설정 → Capabilities의 허용 도메인에 `<지역>.tts.speech.microsoft.com`을 추가합니다(예: `eastasia.tts.speech.microsoft.com`).
3. 리소스의 Keys and Endpoint 화면에서 KEY 1과 지역 이름을 채팅으로 보냅니다.
4. 모든 작업이 끝나면 **Regenerate Key1**로 키를 교체합니다. 키가 대화 기록에 남기 때문입니다.

키를 받으면 화면에 출력하지 말고 저장합니다.
```bash
umask 077; mkdir -p ~/.azkey; printf '%s' 'KEY' > ~/.azkey/key; printf '%s' 'eastasia' > ~/.azkey/region
curl -s -o /tmp/voices.json -w "%{http_code}\n" -H "Ocp-Apim-Subscription-Key: $(cat ~/.azkey/key)" \
  https://$(cat ~/.azkey/region).tts.speech.microsoft.com/cognitiveservices/voices/list
```
- **200**: 정상입니다.
- **000 / 403**: 허용 도메인이 아직 반영되지 않은 것입니다. 2번을 다시 확인하게 합니다.
- **401**: 키가 틀렸거나 이미 재발급된 것입니다.

다른 방법으로 우회하지 않습니다.

## 3. 목소리 고르기

`/tmp/voices.json`에서 대본 언어(예: `zh-CN`, `ko-KR`)와 원하는 성별의 음성 목록을 뽑습니다. SSML 언어는 음성 이름에서 자동으로 정해지고, `--lang`으로 바꿀 수 있습니다. 성격이 다른 후보 6~9개를 골라 같은 대본 대목으로 비교 샘플을 만듭니다. 대목은 인사, 부수·이체자 같은 까다로운 글자, 긴 나열, 결론이 섞이게 고릅니다.
```bash
python3 scripts/narrate_pptx.py samples --text "…대본 일부…" \
  --voices zh-CN-YunyangNeural,zh-CN-YunxiNeural,zh-CN-YunjianNeural,zh-CN-Yunfan:DragonHDFlashLatestNeural \
  --style narration-professional --outdir samples
```
- 일반 음성에 스타일을 지정할 수 있습니다. HD·MAI 계열은 스타일 없이 만듭니다.
- 길이가 음성마다 크게 다르니 함께 알려 줍니다. `--rate -10%`처럼 속도를 바꿀 수 있습니다.
- **Claude는 소리를 들을 수 없습니다.** 발음이 정확한지, 특히 亻·彳 같은 부수 글자나 번체자를 제대로 읽는지는 사용자에게 확인을 맡기고, 확인하지 못했다고 분명히 말합니다. 잘못 읽는 글자는 음성용 대본에서 빼거나 다르게 풀어 씁니다.

## 4. 전체 합성

```bash
python3 scripts/narrate_pptx.py parse deck.pptx -o segs.json
python3 scripts/narrate_pptx.py tts segs.json -o segs_audio.json --voice zh-CN-YunyangNeural --style narration-professional
```
- 무료 등급 속도 제한 때문에 호출 사이에 3.2초씩 쉽니다. 100구간이면 6~7분 걸리니 백그라운드로 돌리고 완료를 기다립니다.
- 음성 파일 이름에는 문장과 음성 설정의 해시가 들어갑니다. 그래서 대본을 고친 뒤 다시 실행하면 바뀐 문장만 새로 합성합니다.

## 5. 【X초】 큐가 있는 클릭: 글자별 효과 묶음 정하기

한 클릭 안에서 효과 여러 개가 시간차로 나오고 노트에 【X초】 문장이 있으면, 각 효과를 어느 문장에 붙일지 정해야 합니다. 이것을 틀리면 "A를 말하는데 B의 상자가 뜨는" 어긋남이 생깁니다.

1. `inspect -v`로 그 클릭의 효과 목록(시작 ms, 도형 이름·글자)을 봅니다.
2. 문장별로 그 문장에 속하는 효과 묶음의 시작 시각(ms)을 큐 순서대로 `bounds`에 적습니다. 묶음 i는 `bounds[i]` 이상, `bounds[i+1]` 미만입니다.
3. `mode`를 고릅니다.
   - `first`: 묶음의 첫 효과가 문장이 시작될 때 나옵니다. 상자 → 화살표 → 이름표처럼 효과가 이름표 앞에 먼저 나오는 패턴에 씁니다.
   - `cue`: 노트의 【X초】 시각에 있던 효과가 문장 시작 0.2초 전에 나오고, 나머지는 원래 간격을 유지합니다. 그림이 나온 뒤 강조 표시가 뒤따르는 패턴에 씁니다.
4. `cues.json`에 `{"슬라이드번호": {"클릭번호": {"mode": "...", "bounds": [...]}}}` 형식으로 씁니다. 예시는 `references/cues_example.json`에 있습니다. 예를 들어 슬라이드 2의 클릭 2에서 상자 → 화살표 → 이름표가 0, 2500, 5000ms부터 세 묶음으로 나오면 `{"2": {"2": {"mode": "first", "bounds": [0, 2500, 5000]}}}`입니다.

`cues.json`을 주지 않으면 기본 규칙을 씁니다. 각 효과를 그 효과 뒤에 오는 첫 큐에 붙이고 `first` 모드로 처리합니다. 효과가 대사보다 먼저 나오는 패턴이면 기본 규칙으로 충분하지만, 강조 효과가 뒤따르는 패턴은 반드시 직접 지정합니다.

어느 모드든 다음 문장은 앞 글자의 효과 간격이 끝난 뒤에 시작합니다. 그래서 짧은 문장 때문에 효과가 겹치지 않습니다.

## 6. 빌드와 검증

```bash
python3 scripts/narrate_pptx.py build deck.pptx segs_audio.json -o "[약칭]_자동발표.pptx" --cues cues.json
```
- 같은 위치에 `*_timeline.md`(문장별 시작 시각), `*_timeline.json`, `*_review.mp3`(전체 낭독 이어 붙임)가 생깁니다.
- 타이밍 조절 옵션(초 단위, 괄호는 기본값):
  - `--slide-lead` 슬라이드가 열린 뒤 첫 낭독까지 (0.7)
  - `--first-click` 열릴 때 읽을 문장이 없을 때 첫 클릭 효과까지 (0.6)
  - `--click-lead` 클릭 효과가 시작된 뒤 낭독까지의 최대 간격 (1.0)
  - `--gap` 낭독이 끝난 뒤 다음 클릭까지 (0.5)
  - `--sentence-gap` 문장 사이 (0.25)
  - `--tail` 마지막 낭독·효과가 끝난 뒤 다음 슬라이드까지 (1.5)
- 검증: pptx 스킬이 있으면 `validate.py out.pptx --original deck.pptx`를 실행합니다. LibreOffice로 PDF로 바꿔 열리는지만 봅니다. LibreOffice는 애니메이션을 재생하지 못하므로, 타이밍은 사용자의 PowerPoint로만 확인할 수 있다고 분명히 말합니다.

## 7. 전달과 사용자 확인 안내

전달할 것: PPTX, 검토용 MP3. 그리고 아래 확인 방법을 안내합니다.
- **재생 확인:** Windows PowerPoint에서 슬라이드 쇼 탭의 **시간 사용**과 **내레이션 재생**이 켜져 있는지 확인하고, 처음부터 시작해 클릭하지 말고 지켜봅니다. 도중에 클릭하면 다음 슬라이드로 넘어갑니다.
- **어긋날 때:** 애니메이션 탭 → 애니메이션 창에서 각 효과의 '지연' 값이 `*_timeline.md`의 시각과 맞는지 봅니다. 그리고 "몇 번 슬라이드, 어느 문장에서, 무엇이 먼저 또는 늦게 뜨는지"를 알려 달라고 합니다.
- **영상 내보내기:** 파일 → 내보내기 → 비디오 만들기 → '녹음된 시간 및 내레이션 사용'. Mac PowerPoint는 영상으로 내보낼 때 애니메이션이 빠지므로 Windows에서 내보내야 합니다.
- **마지막 슬라이드:** 질의응답을 청하는 문장으로 끝나면, 무인 상영에서는 그 문장을 바꾸도록 권합니다.

## 꼭 지킬 것 (실제로 겪은 문제들)

- **'이전 효과 다음에' 묶음의 대기 시간에 의존하지 않습니다.** PowerPoint는 그 값을 무시하고 자체 규칙으로 시간을 다시 계산합니다. 그 결과 사진이 시작하자마자 뜨는 식으로 전부 어긋났습니다. 그래서 `build`는 모든 효과를 한 묶음 안의 **'이전 효과와 함께' + 슬라이드 시작 기준 절대 지연**으로 바꿉니다. 이 구조를 손으로 바꾸지 마세요.
- 음성은 슬라이드마다 하나의 트랙으로 넣습니다. 문장 사이는 무음으로 채워 위치를 맞추고, 슬라이드가 열릴 때 재생을 시작합니다. 아이콘은 슬라이드 밖에 숨겨 둡니다.
- 문장 길이는 WAV로 받아 정확히 잽니다. MP3는 앞뒤 여백 때문에 길이가 어긋납니다.
- 클릭 하나에 효과 여러 개가 시간차로 나오는 경우는 반드시 5단계에서 묶음을 확인합니다. 이번 작업에서 가장 많이 어긋난 곳이 여기였습니다.
- Azure 키는 파일에 남기지 말고, 작업이 끝나면 `rm -rf ~/.azkey`로 지운 뒤 사용자에게 키 재발급을 다시 알립니다.
- 무료 등급(F0)에서도 HD·MAI 음성 호출은 성공했습니다(2026-11 관찰). 다만 요금 정책은 바뀔 수 있으므로, 리소스가 F0인지 사용자에게 확인하게 합니다.
